建立 Data Machi 不一定只有一種開發方式。你可以依照設備、時間與修改範圍，選擇本機、雲端或混合式工作流。

## 路線一：本機開發

```text
VS Code
  ├─ Claude Code
  └─ Codex
      ↓
修改本機 Repository
      ↓
啟動前端與後端測試
      ↓
Push 到 GitHub
```

適合大型修改、查看完整錯誤、測試 PDF／音訊與同時啟動前後端。

## 路線二：雲端開發

```text
桌機或手機
  ↓
Claude Code 雲端環境
  ↓
讀取 GitHub Repository
  ↓
建立 Commit 或 Pull Request
```

適合修改 Prompt、文案、環境變數範例、小型功能與部署問題。雲端環境是否能完整執行專案，取決於它是否支援必要套件、檔案與外部服務。

## 路線三：混合式開發

這是作者主要使用的方法：

| 情境 | 建議方式 |
| --- | --- |
| 第一次啟動與大型架構修改 | 本機 VS Code |
| Prompt、文案、小型修正 | 本機或雲端皆可 |
| 手機臨時修改 | 雲端 Coding Agent |
| PDF、音訊與完整流程測試 | 本機 |
| 查看正式環境狀態 | Render／Vercel Dashboard |

## 不論用哪個工具，都遵循同一流程

```text
描述目標 → AI 先檢查 → 提出計畫 → 修改 → 查看 Diff → 測試 → Commit
```

<Warning>
  不要直接接受所有修改。至少確認改了哪些檔案、是否新增套件、是否把 API Key 寫進程式，以及原本功能是否仍正常。
</Warning>
