30 天系列建立的是企業 AI 工作流的觀念地圖；實作篇則會把這些觀念逐步放進同一個 Data Machi 專案中。這裡不再按照固定天數更新，也不為了湊篇數拆分內容，而是依照真實產品的建構順序，完成一個可執行、可測試、可持續擴充的系統。

## 實作篇的學習方式

每一篇都會回答四個問題：

1. 這個功能解決什麼真實問題？
2. 它在整體架構中位於哪個位置？
3. 如何用程式完成最小可行版本？
4. 如何驗證它真的正確運作？

```text
需求與問題
   ↓
架構判斷
   ↓
最小可行實作
   ↓
測試與觀察
   ↓
再決定是否增加複雜度
```

## 版本原則

實作文章應對應固定的 Git commit 或 tag。文章中的程式碼、環境變數與執行結果，都應能在相同版本中重現，避免主分支持續演進後，舊文章失去可執行性。

<Note>
  實作篇的目標不是一次建立最複雜的 Multi-Agent，而是先完成單一 Coordinator、確定性 Tools、LangGraph 路由、驗證與重試。只有當真實需求出現，再把特定 Node 升級為完整 Agent。
</Note>
