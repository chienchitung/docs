Data Machi 會使用多組 API Key、Token、Service Account JSON 與服務網址。對初學者來說，最容易出錯的不是申請，而是把憑證放錯地方。

## 四個環境的差異

| 設定 | 本機 | Render | Vercel | GitHub |
| --- | --- | --- | --- | --- |
| Gemini API Key | `backend/.env` | Environment | 不放 | 不放 |
| Service Account JSON | `backend/.env` | Environment／Secret | 不放 | 不放 |
| Trello／Confluence Token | `backend/.env` | Environment | 不放 | 不放 |
| Render Backend URL | 前端 `.env` | 不需 | Environment | 可放範例 |
| Vercel 網址 | 不需 | CORS allowlist | 自動產生 | 可寫文件 |

## `.env.example` 的作用

Repository 可以放變數名稱，但不能放真實值：

```env
GOOGLE_API_KEY=
GOOGLE_SERVICE_ACCOUNT_JSON=
TRELLO_API_KEY=
TRELLO_TOKEN=
CONFLUENCE_URL=
VITE_API_BASE_URL=
```

## 三個安全原則

1. 真實憑證不得 Commit 到 GitHub。
2. 前端程式可被使用者看到，因此敏感金鑰不能放在 Vite 前端環境變數。
3. 憑證若曾公開，即使之後刪除，也應立即撤銷並重新建立。

## 請 AI Coding Agent 檢查

```text
請檢查 Repository 是否包含 API Key、Token、Service Account JSON、
正式 Sheet ID 或內部網址。只列出風險位置，不要在回覆中完整顯示憑證。
同時確認 .gitignore 是否排除 .env 與憑證檔。
```

<Warning>
  名稱以 `VITE_` 開頭的環境變數會被打包進前端，不能用來保存秘密。
</Warning>
