完成服務準備後，接下來要把開源 Repository 變成自己的 Data Machi，而不是直接沿用原始專案中的名稱與設定。

## 應該抽象化的內容

- 組織、部門與產品名稱
- 預設 Sheet ID、Board ID、Space Key
- 正式前端與後端網址
- Prompt 中的業務範圍與身份
- 範例資料中的姓名、Email 與指標
- Logo、favicon、頁面標題與說明

## 不應該只做文字取代

品牌名稱可能同時存在於前端、後端 Prompt、README、部署設定與錯誤訊息。請先讓 AI Coding Agent 搜尋完整 Repository，再依用途分類修改。

```text
請掃描整個 Repository，找出所有可能屬於特定組織的識別資訊。
請分成：品牌文字、預設資料來源、正式網址、憑證風險、業務規則。
先列出位置與修改建議，不要立即全部取代。
```

## 建立 `.env.example`

保留變數名稱與用途說明，但不要放真實值。完成後，新的讀者應能只看 README 與 `.env.example`，知道需要申請哪些服務。

## 本篇驗收

- Repository 搜尋不到原始企業名稱。
- 沒有真實 API Key、Token 或 Service Account。
- 專案名稱、Logo 與說明已改成自己的版本。
- 所有環境差異都透過變數控制，而不是寫死在程式中。
