Agent 執行多步驟任務時，使用者不能只看到一個無限旋轉的 loading。前端應把後端的結構化事件轉成人類能理解的進度。

```text
理解問題中
→ 正在查詢結構化資料
→ 正在搜尋指定文件
→ 正在整合與查核
→ 完成
```

## 進度事件格式

```json
{
  "phase": "tool",
  "label": "正在搜尋文件",
  "status": "running",
  "tool": "document_search"
}
```

前端不應顯示內部 Prompt、Chain of Thought 或敏感工具參數，只顯示使用者需要知道的階段、來源類型與成功／失敗狀態。

## 釐清面板

當後端回傳結構化 questions 時，前端應呈現單選、多選或自由輸入，再把結果放入 `clarifications` 欄位重新送出，而不是把選項拼成一段不穩定文字。

## 文件上下文

使用者選取文件後，前端只傳文件識別名稱，不傳本機絕對路徑或敏感儲存資訊。後端再依 allowlist 解析成可搜尋文件。

## 可行動錯誤

每個錯誤卡片至少包含：發生什麼、可能原因、使用者下一步與是否可以重試。不要直接顯示 stack trace。

## 驗收方式

- 多工具執行時能分階段更新狀態。
- 工具失敗後顯示可重試或替代動作。
- 釐清選項能正確回到原任務。
- 使用者能知道本輪實際查了哪些資料類型。
- 完成狀態不會早於最終回答。
