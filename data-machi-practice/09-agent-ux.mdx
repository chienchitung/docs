當 Agent 需要查資料、搜尋文件、驗證答案時，回應時間可能比一般聊天更長。若畫面只有一個轉圈圈，使用者不知道系統是在工作、卡住，還是已經失敗。

Agent UX 的重點不是做得花俏，而是讓使用者理解：**系統現在在哪個階段、需要我做什麼、最後是否真的完成。**

## 進度訊息必須來自真實狀態

不建議讓模型先說「我正在查詢」，因為模型可能只是產生一句文字，工具其實還沒開始。更可靠的方式是由後端節點發出事件：

```text
analyzing     正在理解問題
querying      正在查詢資料來源
retrieving    正在搜尋文件
verifying     正在檢查答案
completed     已完成
```

前端只負責把這些狀態轉成使用者看得懂的文案。

## Step 1：建立統一的進度事件

```python
payload = {
    "phase": "querying",
    "label": "正在查詢結構化資料",
    "tool": "spreadsheet_query"
}
```

不要把內部函式名稱直接顯示給一般使用者。`tool` 可以留給 Debug，`label` 則應該使用人類可理解的說法。

## Step 2：前端建立狀態列

```text
✓ 已理解問題
✓ 已取得資料
● 正在搜尋文件
○ 尚未進行答案查核
```

使用者不需要看見模型的私人推理內容，只需要看見可驗證的執行階段。

## Step 3：建立釐清面板

當條件不足時，不要在聊天中丟出一大段問題。可以用選項面板：

```text
你想查看哪個期間？
[ 最近 7 天 ] [ 本月 ] [ 本季 ] [ 自訂 ]
```

選擇後，把穩定的 `value` 回傳後端，例如 `current_month`，而不是只傳顯示文字。

## Step 4：讓使用者控制文件範圍

文件側欄可以顯示已上傳文件，讓使用者勾選本輪要使用的內容。這能降低錯誤引用，也讓「為什麼這次沒查某份文件」變得透明。

```json
{
  "active_documents": [
    "demo_policy.pdf",
    "demo_project_guide.pdf"
  ]
}
```

## Step 5：設計可行動錯誤

錯誤訊息應包含下一步：

| 錯誤 | 建議行動 |
| --- | --- |
| 缺少 API Key | 開啟設定並填入金鑰 |
| PDF 尚未處理 | 等待處理完成或重新上傳 |
| 找不到資料 | 改用更精確關鍵字 |
| 模型逾時 | 縮小問題範圍或稍後重試 |

純粹顯示「Something went wrong」對使用者沒有幫助。

## Step 6：區分草稿、完成與失敗

前端應明確知道回答目前是：

- 仍在生成
- 已生成但正在驗證
- 已完成
- 部分完成
- 失敗

否則使用者可能在答案尚未完成時就複製或採取行動。

## 初學者的測試方式

可以刻意製造以下情境：

- 將模型 Timeout 設得很短，確認逾時提示
- 不選文件，確認文件搜尋不會誤用全部來源
- 輸入模糊問題，確認釐清面板出現
- 讓一個工具拋出例外，確認其他工具狀態仍能顯示
- 重新整理頁面，確認需要保留的狀態是否還存在

<Info>
  好的 Agent UX 不會假裝 AI 永遠正確，而是讓使用者隨時知道系統做了什麼、沒做到什麼，以及接下來能採取什麼行動。
</Info>
