在這套開發流程中，GitHub 不只是放程式碼的地方，而是整個專案的共同中心。

```text
本機 VS Code ─┐
              ├→ GitHub Repository → Render 後端
雲端 Agent ───┘                    → Vercel 前端
```

## 建立自己的專案副本

你可以 Fork 開源專案，或建立新的 Repository 再複製程式碼。公開教學版本應先移除組織名稱、真實資料來源、預設 Sheet ID、看板 ID 與正式網址。

## 為什麼 GitHub 是唯一正式來源？

如果本機、雲端環境與正式部署各自保存不同版本，很快就會不知道哪一份才是最新的。比較安全的做法是：所有正式修改都必須回到 GitHub，Vercel 與 Render 只部署 GitHub 中指定分支的內容。

## 建議的 Vibe Coding Prompt

```text
請先閱讀目前 Repository 的資料夾結構、README 與部署設定。
不要立即修改。請先說明：
1. 前端與後端位於哪裡
2. 哪些檔案含有品牌或環境相關設定
3. 哪些內容需要抽象化
4. 預計修改哪些檔案
```
