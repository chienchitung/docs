當 System Prompt 開始同時包含身份、禁止事項、工具規則、資料 schema、輸出格式與語氣要求時，單一大字串會快速失控。Data Machi 的做法是把規則拆成有優先順序的模組。

```text
Layer 1｜Hard Constraints
Layer 2｜Core Identity
Layer 3｜Workflow Policy
Layer 4｜Tool Routing / Data Schema
Layer 5｜Response Formatting
Layer 6｜Skills / Glossary
```

## 載入 Prompt 模組

```python
from pathlib import Path

PROMPT_DIR = Path(__file__).parent.parent / "prompts"

PROMPT_MODULES = {
    "Hard Constraints": "hard_constraints.md",
    "Core Identity": "core_identity.md",
    "Workflow Policy": "workflow_policy.md",
    "Tool Routing": "tool_routing.md",
    "Data Schema": "data_schema.md",
    "Response Formatting": "response_formatting.md",
}

def load_prompt_modules() -> str:
    sections = []
    for title, filename in PROMPT_MODULES.items():
        content = (PROMPT_DIR / filename).read_text(encoding="utf-8").strip()
        sections.append(f"## {title}\n\n{content}")
    return "\n\n".join(sections)
```

## 為什麼需要優先順序？

不同規則可能互相衝突，例如「保持友善」不能覆蓋「資料不足時禁止猜測」。明確的 Layer 可以讓團隊知道哪一條規則具有最高優先權，也讓修改更容易審查。

## 去識別化原則

教學版 Prompt 不應出現真實組織名稱、部門、人名、資料網址、內部縮寫或實際政策內容。請改用：

- `Your Organization`
- `Project Board`
- `Knowledge Base`
- `Structured Data Source`
- 自訂測試 glossary

## 驗收方式

- 刪除任一非必要 Prompt 模組後，系統仍能啟動。
- 高優先級規則不會被低優先級語氣要求覆蓋。
- 工具 schema 修改時，只需更新對應模組。
- Prompt 檔案可以單獨進行版本比較與 review。
