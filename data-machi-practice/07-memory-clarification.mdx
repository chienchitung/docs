多輪對話的難點不是把所有歷史訊息全部塞回 Prompt，而是判斷哪些資訊應沿用、哪些需要重新查詢。

## 四種上下文

| 類型 | 用途 |
| --- | --- |
| 近期對話 | 處理代名詞與直接追問 |
| 摘要記憶 | 壓縮較早但仍重要的脈絡 |
| 先前工具結果 | 支援「幫我再整理成表格」等延續需求 |
| Turn Context | 判斷這輪是新問題、追問、改寫或要求最新資料 |

```text
最新訊息
  ↓
關係分類
  ├─ 延續前文 → 帶入 prior tool context
  ├─ 格式改寫 → 不重新查工具
  ├─ 要求最新 → 強制重新查詢
  └─ 條件不足 → 產生 clarification
```

## 限制上下文大小

近期對話只保留固定則數，較早內容改成摘要；每筆工具結果與會議內容也要有字元上限。無限制堆疊會增加成本、延遲與錯誤判斷。

## 釐清問題

釐清不應只是自由文字。建議回傳結構化問題與選項，讓前端呈現成可選面板，再把選擇結果加入下一次 ChatRequest。

## 驗收方式

- 「剛才那份資料」能正確引用前一輪結果。
- 「請查最新數字」一定重新呼叫工具。
- 長對話不會無限制增加 token。
- 條件不足時先釐清，而不是自行猜測。
- 新主題不會被舊工具結果污染。
