單輪聊天只要處理眼前問題；多輪對話則困難得多。使用者可能只說「那去年呢？」、「改成另一個市場」或「剛剛第二點再展開」。這些句子單獨看沒有完整意義，系統必須知道它們和前文的關係。

## 記憶不是把所有對話全部塞進 Prompt

最直覺的做法是每次都傳送完整歷史，但對話越長，成本、延遲與干擾也越高。成熟系統會把記憶拆成不同層次。

<CardGroup cols={3}>
  <Card title="近期訊息" icon="clock">
    保留最近幾輪原文，處理代名詞、追問與語氣延續。
  </Card>

  <Card title="摘要記憶" icon="file-lines">

  </Card>

  <Card title="工具結果" icon="database">
    保存先前查到的資料，讓合理追問可以重用，不必重查。

## Step 1：用 Conversation ID 區分對話

```python
class ChatRequest(BaseModel):
    message: str
    conversation_id: str | None = None
```

`conversation_id` 就像對話資料夾名稱。沒有它，後端無法判斷兩個請求是不是同一段對話。

## Step 2：限制近期訊息數量

```python
RECENT_CONTEXT_MESSAGES = 18
```

這不是越多越好。保留太多內容，可能讓舊條件干擾新問題。可以先從 10–20 則開始，再透過真實對話測試調整。

## Step 3：建立 Turn Context 判斷

每一輪先分類最新訊息和前文的關係：

```json
{
  "relation": "context_follow_up",
  "should_answer_from_context": false,
  "should_include_prior_tool_context": true,
  "should_force_fresh_tool": true
}
```

白話來說，系統要判斷：

- 這是全新問題嗎？
- 是在追問剛才的答案嗎？
- 可以沿用先前資料嗎？
- 使用者是否要求「最新」而必須重查？

## Step 4：哪些情況可以重用工具結果？

例如先問：

```text
2025 年完成多少件需求？
```

接著問：

```text
其中哪個部門最多？
```

若先前工具結果已包含部門欄位，可以重用；但若接著問：

```text
今天最新的狀況呢？
```

就必須重新查詢，因為「最新」代表資料可能已改變。

## Step 5：設計釐清流程

當必要條件缺少時，不要讓模型自己猜。

```text
使用者：請分析最近的資料
系統：你想查看哪個期間？
       ○ 最近 7 天
       ○ 本月
       ○ 本季
       ○ 自訂期間
```

釐清不是聊天上的禮貌，而是降低錯誤查詢的重要 Node。

## Step 6：把選擇結果放回請求

```json
{
  "question": "你想查看哪個期間？",
  "label": "本月",
  "value": "current_month"
}
```

後端應使用 `value` 作為穩定的程式參數，而不是再次解析畫面上的中文標籤。

## 測試情境

- 「那另一個市場呢？」能延續前文
- 「改成去年」會保留指標、替換期間
- 「最新狀況」會強制重查
- 新問題不會誤用舊工具結果
- 缺少期間時會提出釐清
- 對話過長時仍能保留最重要背景

<Info>
  好的記憶設計不是讓 Agent 記住最多，而是讓它知道哪些內容可以沿用、哪些必須重新取得。
</Info>
