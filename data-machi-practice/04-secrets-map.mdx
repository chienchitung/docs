Data Machi 會使用多種 API Key、Token、網址與 Service Account 憑證。最常見的問題不是不會申請，而是**不知道取得之後應該放在哪裡**。

```mermaid
flowchart TD
    A[取得 API Key / Token] --> B{前端需要直接使用嗎？}
    B -- 否 --> C[放 backend/.env 或 Render Environment]
    B -- 是且可公開 --> D[放 Vercel Environment]
    B -- 是但屬於 Secret --> E[改由後端代理，不放前端]
    C --> F[加入 .gitignore]
    D --> G[重新部署前端]
```

## 四個位置的差異

| 位置 | 適合放什麼 | 不應放什麼 |
| --- | --- | --- |
| `backend/.env` | 本機 Gemini、Trello、Confluence、Sheets 憑證 | 不提交 GitHub |
| Render Environment | 正式後端 Secret 與服務設定 | 不放在公開程式碼 |
| Vercel Environment | 前端需要的 Backend URL、公開設定 | 私密 API Key |
| GitHub | `.env.example`、變數名稱與說明 | 真實 Key、Token、JSON |

## Data Machi 的 Secret 地圖

```env
# 後端：本機 .env / Render Environment
GOOGLE_API_KEY=
GOOGLE_SERVICE_ACCOUNT_JSON=
TRELLO_API_KEY=
TRELLO_TOKEN=
CONFLUENCE_API_TOKEN=

# 前端：本機 .env / Vercel Environment
VITE_API_BASE_URL=
```

<Warning>
  任何以 `VITE_` 開頭的變數，都可能被打包進瀏覽器可以讀取的前端程式。不要把 Gemini、Trello、Confluence 或 Service Account Secret 放在前端。
</Warning>

## 本機與正式環境為什麼要分開？

本機 `.env` 只存在你的電腦；Render 與 Vercel 不會自動讀取它。部署後必須到各平台 Dashboard 重新建立對應的 Environment Variables。反過來，平台上的 Secret 也不會自動下載到本機。

## 建立專案環境變數

### 步驟 1：建立本機 `.env`

在 `backend` 資料夾建立 `.env`，放入本機實際使用的 Secret。前端若需要環境變數，只放可公開設定，例如 Backend URL。

### 步驟 2：建立 `.env.example`

在 Repository 中保留 `.env.example`，只列出變數名稱與用途，不要放入任何真實值。

### 步驟 3：使用 `.gitignore` 排除敏感檔案

開啟 Repository 根目錄的 `.gitignore`，加入 `.env`、Service Account JSON、索引檔與其他本機產生檔案。若檔案曾經被 Git 追蹤，只修改 `.gitignore` 並不會自動移除歷史紀錄，還要另外停止追蹤並檢查 Git 歷史。

### 步驟 4：在 Render 建立後端 Secret

進入 Render Web Service 的 Environment 頁面，新增 Gemini、Google Sheets、Trello 與 Confluence 等後端變數。確認名稱與程式讀取名稱完全一致，儲存後重新部署或重新啟動服務。

### 步驟 5：在 Vercel 建立前端環境變數

進入 Vercel Project Settings 的 Environment Variables，新增 `VITE_API_BASE_URL` 等可公開設定，選擇 Production、Preview 與 Development 的套用範圍，儲存後重新部署前端。

### 步驟 6：重新部署並驗證

完成 Render 與 Vercel 設定後，重新部署兩個服務，確認後端能讀取 Secret、前端能讀取公開設定，且 GitHub 中沒有出現任何真實值。

## 本篇驗收

- `.gitignore` 已排除 `.env`、金鑰 JSON 與本機索引檔。
- GitHub 只保留 `.env.example`，內容沒有真實值。
- 前端只保存 Backend URL 等可公開設定。
- 每次新增環境變數後，都知道是否需要重新部署。

<Note>
  把 Secret 放對位置，只解決「不要外漩」；它不代表憑證的所有權、權限範圍與離職交接已經完成。正式部署前，還要在〈實作 17｜權限與資訊安全〉盤點資產所有者、備援管理者、最小權限與 Token 輪替方式。
</Note>
