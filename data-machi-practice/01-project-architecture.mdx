第一次看到一個完整的 AI Agent 專案，最容易卡住的地方通常不是程式碼，而是不知道「應該先看哪裡」。資料夾很多、檔案很多、前端與後端又分開，還有模型、工具、向量資料庫與外部 API。若一開始就逐行閱讀，很容易迷失。

這一篇不急著修改功能，而是先完成兩件事：**把系統成功跑起來，以及看懂一個問題從畫面進入系統後，經過哪些模組才形成答案。**

## 先用餐廳理解前後端

可以把整個系統想成一間餐廳：

<CardGroup cols={2}>
  <Card title="前端：外場與菜單" icon="display">
    使用者看到的聊天畫面、輸入框、文件上傳、進度提示與錯誤訊息，都屬於前端。它負責收集需求與呈現結果，但不直接執行 AI 推理。
  </Card>

  <Card title="後端：廚房與出餐流程" icon="server">
    後端接收前端送來的請求，呼叫模型與工具、查詢資料、保存對話狀態，再將結果傳回前端。
  </Card>
</CardGroup>

Data Machi 的前端採用 React 與 Vite，後端則採用 Python 與 FastAPI。兩者必須分別啟動，就像餐廳需要外場與廚房同時運作。

## 先看懂專案地圖

```text
project-root/
├─ frontend/                 使用者介面
│  ├─ src/                   React 元件與畫面邏輯
│  └─ package.json           前端套件與啟動指令
│
├─ backend/                  AI 與資料處理
│  ├─ main.py                FastAPI 入口
│  ├─ agent_logic.py         一輪對話的主要流程
│  ├─ agents/                Coordinator 與各類工具
│  ├─ prompts/               模組化系統規則
│  ├─ conversation_store.py  對話與工具結果保存
│  └─ requirements.txt       Python 套件
│
└─ render.yaml               後端部署設定
```

<Info>
  初學者不需要一開始看完所有檔案。先記住三個入口：前端從 `frontend/` 啟動，後端從 `backend/main.py` 啟動，一輪 AI 對話主要由 `agent_logic.py` 與 `agents/coordinator.py` 協作完成。
</Info>

## Step 1：準備環境

請先安裝：

- Node.js 20 以上
- Python 3.11 或 3.12
- Git

確認版本：

```bash
node --version
python3 --version
git --version
```

若終端機顯示找不到指令，代表尚未安裝，不能直接進入下一步。

## Step 2：取得專案

```bash
git clone https://github.com/chienchitung/ikea-data-agent.git
cd ikea-data-agent
```

雖然 Repository 名稱保留原始名稱，實作文章中會將它視為一個通用的企業知識工作流範例，不使用真實企業資料。

## Step 3：啟動後端

開啟第一個終端機：

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Windows PowerShell 啟用虛擬環境的方式不同：

```powershell
.venv\Scripts\Activate.ps1
```

接著建立 `backend/.env`：

```env
GOOGLE_API_KEY=your_api_key
GEMINI_MODEL=your_primary_model
GEMINI_FAST_MODEL=your_fast_model
ALLOWED_ORIGINS=http://localhost:5173
```

啟動後端：

```bash
python main.py
```

看到 `Uvicorn running on http://0.0.0.0:8000`，代表廚房已經開始營業。

## Step 4：啟動前端

開啟第二個終端機：

```bash
cd frontend
npm install
npm run dev
```

瀏覽器打開：

```text
http://localhost:5173
```

## 一則訊息實際經過哪些步驟？

```text
使用者輸入問題
   ↓
React 前端送出 HTTP Request
   ↓
FastAPI 驗證資料格式
   ↓
agent_logic.py 準備對話脈絡
   ↓
Coordinator 判斷是否需要工具
   ↓
工具查詢資料／文件
   ↓
模型整合答案
   ↓
FastAPI 回傳 JSON
   ↓
前端顯示結果
```

這條路徑就是後續所有實作文章的主線。

## 驗收清單

完成本篇後，請確認：

- 前端網址可以開啟
- 後端 `/docs` 頁面可以開啟
- 瀏覽器 Console 沒有 CORS 錯誤
- 後端終端機能看到請求紀錄
- 沒有把 `.env` 或金鑰提交到 Git

<Warning>
  最常見的問題是只啟動前端，卻忘記啟動後端。此時畫面可能正常，但送出訊息會出現連線失敗。另一個常見問題是把 API Key 直接寫進程式碼，這會讓金鑰被提交到公開 Repository。
</Warning>

下一篇會進入後端入口，理解前端送來的資料為什麼需要先經過 API 契約，而不能直接把任意內容丟給 Agent。
