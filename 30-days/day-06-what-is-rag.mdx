通用 AI 模型在訓練完成後，對外部世界的知識就此凍結——它不認識你的公司規章、不知道最新版本的操作手冊、也看不到昨天才更新的合約範本。然而，企業真正需要的，恰恰是這些「訓練資料之外」的私有知識。RAG（Retrieval-Augmented Generation，檢索增強生成）就是為了解決這個矛盾而生的架構：在模型開口回答之前，先幫它把相關資料找出來，再一起交給模型，讓它根據這些內容作答。

## 什麼是 RAG？

RAG 的全名是 **Retrieval-Augmented Generation**，中文常譯為「檢索增強生成」。顧名思義，它在「生成答案」之前，多了一道「檢索」步驟。整個流程可以用一個大家都熟悉的情境來理解：**開卷考試**。

閉卷考試要求學生靠記憶作答，等同於只使用模型訓練時學到的知識；開卷考試則允許翻閱資料，等同於在回答前先查找相關文件。RAG 就是把 AI 從閉卷考試，升級成開卷考試的機制。模型仍然負責閱讀、理解與表達，但它不再只能依靠過去的訓練記憶，而是可以先翻閱企業提供的參考資料。

<Steps>
  <Step title="Retrieval：根據問題檢索相關片段">
    系統接收到使用者的問題後，先將問題轉換成向量（Embedding），再在知識庫中搜尋語意最相近的文件片段（Chunk）。這一步決定了模型能看到哪些參考資料。
  </Step>
  <Step title="Augmentation：將資料注入上下文">
    把找到的文件片段與原始問題組合在一起，構成一段完整的 Prompt。這份 Prompt 會明確告訴模型：「請根據以下資料回答問題，不要自行臆測資料以外的內容。」
  </Step>
  <Step title="Generation：模型根據資料生成答案">
    模型只根據被注入的文件內容整理答案，並可以標示資料來源（文件名稱、頁碼、段落）。這讓答案具有可追溯性，而非憑空生成。
  </Step>
</Steps>

## RAG 解決了哪三件事？

RAG 架構的設計，主要是針對企業 AI 應用中最常見的三個痛點。

<CardGroup cols={3}>
  <Card title="私有資料不可見" icon="lock">
    模型訓練資料不包含企業內部文件。RAG 讓模型在回答時能取用企業自有的知識庫，而無需重新訓練模型。
  </Card>

  <Card title="資料持續更新" icon="arrows-rotate">
    企業的規範、流程與產品資訊頻繁變動。RAG 只需更新知識庫文件，不需要每次都重新微調模型。
  </Card>

  <Card title="答案需要來源佐證" icon="file-magnifying-glass">
    在法務、合規與稽核場景中，「AI 說的」不夠，必須能對應到具體的文件頁碼與段落，才有說服力。
  </Card>
</CardGroup>

## Data Machi 實戰：Document Tool 如何運作

在 Data Machi 平台中，**Document Tool** 就是 RAG 的具體實作。當 Agent 收到問題，Document Tool 會搜尋已上傳的 PDF 知識庫，回傳最相關的文件片段，同時附上文件名稱與頁碼。模型取得這些內容後，再生成答案並標示來源。

這讓以下類型的問題有了可靠且可追溯的依據：

- 「公司差旅報銷規範是什麼？」
- 「操作手冊第幾頁有提到緊急停機流程？」
- 「最新版本的合約範本裡，保密條款怎麼寫？」

```text
使用者問題：「員工出差申請需要提前幾天送出？」

[Document Tool 搜尋知識庫]
→ 命中：差旅管理辦法.pdf，第 3 頁，第 2 條
→ 內容：「出差申請應於出發日前五個工作天提出……」

[模型生成答案]
→ 「根據差旅管理辦法第 3 頁，員工出差申請應於出發日前五個工作天提出。」
```

## RAG 的邊界：它不解決什麼

理解 RAG 的能力，也必須清楚它的限制，避免對它抱持不切實際的期待。

<Warning>
  RAG 並不保證一定能找到答案。如果知識庫中根本沒有相關文件，或文件品質不佳（掃描模糊、切割不當），RAG 也無能為力。
</Warning>

<Note>
  RAG 不會自動完成跨系統的工作。它只是「把資料找出來」，不代表它能讀取即時數據、執行計算、或觸發下游流程。這些需求需要結合 Tool Use 與 Agent 架構。
</Note>

## 常見誤區：資料塞越多越好？

很多人在第一次建立 RAG 系統時，會有一個直覺：「把整份文件全部交給模型，它不就什麼都知道了？」

<Tip>
  RAG 的目標不是把整份文件全部塞給模型，而是精準找出最相關的段落。無關資訊反而會稀釋真正重要的內容，讓模型在大量文字中迷失，降低答案品質。
</Tip>

好的 RAG 系統追求的是「精準」而非「全量」：在對的時間，把對的內容，遞給模型。

<Accordion title="補充：RAG 與 Fine-tuning 有什麼差別？">
  Fine-tuning（微調）是直接修改模型的參數，讓模型「記住」特定知識。這適合風格調整或特定任務的能力強化，但成本高、更新慢，且很難讓答案對應到具體來源文件。

  RAG 則完全不碰模型本身，而是透過「查資料」的方式補充知識。知識庫可以隨時更新，答案可以對應來源，適合企業私有知識的查詢場景。

  兩者並不互斥，成熟的企業 AI 系統有時會同時使用微調（調整語氣與格式）加上 RAG（補充即時知識）。
</Accordion>

<Info>
  今天只要記住一件事：RAG 不是重新訓練模型，而是在模型回答前，替它準備正確的參考資料。
</Info>
