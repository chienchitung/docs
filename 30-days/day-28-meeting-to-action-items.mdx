企業中大量的決策與知識在會議中產生，卻很少能有效地流入可搜尋、可追蹤的工作系統。一段錄音只是保存了聲音；真正有價值的，是把討論內容轉化成摘要、決議、行動項目，並讓這些資訊能夠被後續跟進。這正是 AI 工作流能發揮最大槓桿效益的場景之一。

## 整條工作流的全貌

```text
錄音（瀏覽器 / 上傳）
  → 音訊正規化（ffmpeg）
    → 長音檔分段處理
      → Whisper 語音轉錄（Groq API）
        → 結構化會議記錄（Gemini / GPT-4o）
          → Action Items 提取
            → 匯入任務看板
              → 後續追蹤與會議上下文重用
```

這條流程中，每一個環節都有設計決策，也都有常見的踩坑點。

## 逐步拆解每個環節

<Steps>
  <Step title="音訊正規化：讓 Whisper 更容易轉錄">
    瀏覽器錄製的音訊格式多樣（WebM、OGG、MP4），取樣率和聲道數也不一致。在送入 Whisper 前，先用 **ffmpeg** 統一處理，能顯著提升轉錄準確率。

    ```bash
    # 將任意格式音訊轉換為 Whisper 偏好的格式
    ffmpeg -i input_audio.webm \
      -ar 16000 \        # 取樣率 16kHz
      -ac 1 \            # 單聲道
      -c:a pcm_s16le \   # PCM 16-bit
      output_audio.wav
    ```

    <Tip>
      Whisper 官方建議使用 16kHz 單聲道 WAV 格式。預先正規化可以讓轉錄更快、更準確，尤其對多人同時講話的會議場景幫助明顯。
    </Tip>
  </Step>

  <Step title="長音檔分段：處理上傳限制">
    Whisper API 有單次上傳的檔案大小限制（Groq 約 25MB）。超過 30 分鐘的會議錄音通常需要切割。

    分段策略需注意：

    - **切割點要避開句子中間**，盡量在靜音處切割，保留語意完整性
    - **保留前後重疊片段**，確保跨段落的對話不被截斷
    - **平行處理各分段**，縮短整體轉錄等待時間

    ```python
    from pydub import AudioSegment
    from pydub.silence import detect_nonsilent

    def split_audio_by_silence(audio_path: str, max_chunk_ms: int = 600_000):
        """在靜音處切割音訊，每段不超過 max_chunk_ms 毫秒"""
        audio = AudioSegment.from_file(audio_path)
        chunks = []
        start = 0

        while start < len(audio):
            end = min(start + max_chunk_ms, len(audio))
            # 在 end 前後 30 秒內尋找靜音點
            search_region = audio[max(start, end - 30_000):end]
            silence_ranges = detect_nonsilent(search_region, min_silence_len=500, silence_thresh=-40)

            if silence_ranges:
                # 在靜音點切割
                cut_point = start + (end - 30_000) + silence_ranges[-1][0]
            else:
                cut_point = end

            chunks.append(audio[start:cut_point])
            start = cut_point

        return chunks
    ```
  </Step>

  <Step title="Whisper 語音轉錄">
    Data Machi 使用 Groq 提供的 Whisper 端點，速度比 OpenAI 原生 Whisper API 快數倍。

    ```python
    from groq import Groq

    client = Groq()

    async def transcribe_audio_chunk(audio_path: str, language: str = "zh") -> str:
        with open(audio_path, "rb") as audio_file:
            transcription = client.audio.transcriptions.create(
                file=(audio_path, audio_file.read()),
                model="whisper-large-v3",
                language=language,
                response_format="verbose_json",  # 包含時間戳記
                timestamp_granularities=["segment"]
            )
        return transcription.text

    async def transcribe_full_meeting(chunks: list) -> str:
        """並行處理所有分段，合併結果"""
        tasks = [transcribe_audio_chunk(chunk) for chunk in chunks]
        results = await asyncio.gather(*tasks)
        return "\n".join(results)
    ```

    <Note>
      如果會議涉及專業術語或英中混用，可以在 `prompt` 參數中提供術語提示，顯著提升特定詞彙的辨識準確率。
    </Note>
  </Step>

  <Step title="結構化會議記錄：用固定 Schema 穩定輸出">
    逐字稿轉入 LLM 後，要求模型輸出**固定 JSON Schema**，而非自由格式的「整理會議」。這是確保後續自動化處理能穩定運作的關鍵。

    ```python
    MEETING_NOTES_SCHEMA = {
        "executive_summary": "string",        # 2-3 句話的重點摘要
        "attendees": ["string"],               # 出席人員列表
        "agenda_items": [
            {
                "title": "string",
                "discussion": "string",
                "decisions": ["string"]
            }
        ],
        "action_items": [
            {
                "task": "string",              # 任務描述
                "assignee": "string | null",   # 負責人（若有提及）
                "due_date": "string | null",   # 期限（若有提及）
                "priority": "high | medium | low"
            }
        ],
        "key_decisions": ["string"],
        "follow_up_questions": ["string"]      # 需要後續確認的問題
    }
    ```

    ```python
    async def generate_meeting_notes(transcript: str) -> dict:
        prompt = f"""
    你是一位專業的會議記錄助理。請根據以下逐字稿，輸出結構化的會議記錄。

    重要規則：
    1. action_items 的 assignee 和 due_date，只填寫逐字稿中明確提及的資訊，不要自行推測
    2. 若負責人未提及，assignee 填 null
    3. 輸出必須是合法的 JSON，符合提供的 schema

    逐字稿：
    {transcript}

    請輸出 JSON：
    """
        response = await call_llm(prompt, response_format={"type": "json_object"})
        return json.loads(response)
    ```
  </Step>

  <Step title="Action Items 匯入看板與後續追蹤">
    結構化輸出的真正價值，在於能自動將行動項目匯入任務系統，並與原始會議保持連結。

    ```typescript
    // 將 action items 匯入任務看板
    async function importActionItems(meetingId: string, actionItems: ActionItem[]) {
      const tasks = actionItems.map(item => ({
        title: item.task,
        assignee: item.assignee ?? "待指派",
        dueDate: item.due_date,
        priority: item.priority,
        sourceType: "meeting",
        sourceMeetingId: meetingId,   // 保留來源會議連結
        status: "todo"
      }));

      await db.tasks.createMany({ data: tasks });
    }
    ```

    使用者也可以將選定的會議記錄重新加入聊天上下文，進行後續追問：

    ```text
    使用者：上週三的產品會議裡，關於 API 權限的討論決定了什麼？
    Agent：根據 2024/01/17 的產品週會記錄，團隊決定：
           1. API 權限採用角色分層設計，共分三級
           2. 第一版先實作 read-only 與 read-write 兩種角色
           3. 負責人：工程部 Eason，預計兩週內提出設計稿
    ```
  </Step>
</Steps>

## 為什麼一定要結構化輸出？

<CardGroup cols={2}>
  <Card title="格式穩定，自動化才能運作" icon="table">
    只有固定 schema 的 JSON 輸出，才能穩定地自動匯入看板、觸發通知、更新狀態追蹤系統。自由格式文字每次長相不同，無法可靠地解析。
  </Card>
  <Card title="欄位明確，避免模型臆測" icon="shield-check">
    明確定義哪些欄位可以為 null，讓模型在資訊不足時留空，而不是自行捏造負責人或期限。這是保持資料品質的關鍵守則。
  </Card>
  <Card title="來源可追溯" icon="link">
    每個 action item 都連結到原始會議 ID，讓任何人都能回頭查看決策背景，而不只是看到一個孤立的待辦事項。
  </Card>
  <Card title="可搜尋、可查詢" icon="magnifying-glass">
    結構化資料可以支援「找出所有指派給 Alice 但尚未完成的行動項目」這類跨會議的精確查詢。
  </Card>
</CardGroup>

## 踩坑筆記

<Warning>
  **不能讓模型自行填補缺失資訊。** 逐字稿沒有提到負責人或期限時，欄位應該留空（null），絕對不能由模型根據猜測自行分派。Action Items 進入工作系統後，不明確的指派比空白更危險，因為它會讓人以為已有人負責。
</Warning>

<Accordion title="長音檔的記憶體與處理時間問題">
  60 分鐘以上的會議錄音，轉錄本身可能就需要 2–5 分鐘。若在同步 HTTP 請求中處理，容易觸發 Gateway Timeout。建議的做法：

  1. 接收上傳後立即回傳任務 ID（非同步處理）
  2. 後端排隊執行轉錄 + 摘要流程
  3. 完成後透過 WebSocket 或輪詢通知前端
  4. 提供處理進度（「已轉錄 3/5 段...」）

  這樣即使處理需要數分鐘，使用者也不會遇到頁面無回應的問題。
</Accordion>

<Accordion title="多語言與專業術語的轉錄挑戰">
  台灣企業會議常見中英夾雜（Chinglish），加上產業術語、人名、專案代號等，Whisper 預設設定可能產生誤判。改善方式：

  - 在 `prompt` 參數提供常見術語列表（產品名稱、人名、技術詞彙）
  - 針對特定產業訓練或 Fine-tune 自訂 Whisper 模型
  - 轉錄後加入「術語校正」步驟，用規則替換常見誤識別詞
</Accordion>
